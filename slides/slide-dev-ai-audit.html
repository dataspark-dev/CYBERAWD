AI OUTPUT IS UNTRUSTED CODE

AppSec Secrets Git Lifecycle AI Code Audit Prompt Injection Golden Rules

Code from an AI assistant gets the same scrutiny as code from a stranger on the internet — because that's effectively what it is.

Hallucinated Package Names Risk

AI assistants sometimes invent a plausible-sounding package that doesn't exist — an attacker who registers that exact name under a popular ecosystem is now one install away from your machine.

Verify Before You Install Good Practice

Check that a suggested package actually exists, and check its publish history and maintainer, before adding it to a project — the same check as any other new dependency.

Flawed Logic, Weak Ciphers Risk

AI-generated code can look clean while using a deprecated cipher, a flawed auth check, or an off-by-one that only shows up under load — confident-looking code is not the same as correct code.

Review Like Any Third-Party Contribution Good Practice

Read it the way you'd read a stranger's pull request — line by line, not skimmed because it compiled and the tests passed.

This connects directly to this month's activities: the fake-dependency scenario in Fault Finding is the exact failure mode a hallucinated package name creates — a name that sounds right is not the same as a name that's real.
