Dozens of routine notifications a day — a PR comment, a CI result, a dependency update — are exactly what attackers copy, because you're trained to move through them fast.

Fake Dependency Request
A plausible package name is not a safety check — verify publish history and maintainer reputation yourself.
Phishing via PR Comment
GitHub never asks you to “re-authorize” through a link in a comment — open github.com yourself instead.
Fake Recruiter Outreach
An unsolicited coding challenge that asks you to run a setup script is a known way to deliver malware.
CI/CD Credential Phishing
Your CI system authenticates through your session — it never asks you to retype credentials by email.
Dependency Review
Reading the PR's diff doesn't tell you what a new package does at install time — check the package itself.
Keep practicing: live awareness games (4 rotating stations, ~30–45 min, team scoring) continue this training in person.
A familiar package name, a real-looking reviewer handle, or a routine-looking CI alert is not proof: STOP → VERIFY by opening the real site yourself → REPORT. Every single time.
