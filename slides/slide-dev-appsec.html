Three vulnerability classes account for most real-world app breaches — get these right before anything else.

Server-Side Input Validation Good Practice

Client-side validation is a UX nicety, not a security control — every input is re-validated on the server, because the client is never trusted.

Broken Access Control Risk

Checking a user is logged in is not the same as checking they're allowed to see THIS record — authorize every request against the specific resource, not just the session.

SSRF & Injection Risk

A server that fetches a URL or builds a query from user input can be tricked into reaching internal systems or executing unintended commands — sanitize and allow-list, never string-concatenate.

Least-Privilege Service Accounts Good Practice

The service account your app runs as should only reach what it must — this is what limits the blast radius when one of the above is missed anyway.

This connects directly to this month's activities: the fake-dependency and CI/CD-phishing scenarios in Fault Finding and Decision Room assume attackers already know these 3 classes — so should you, before you ever get to secrets or pipelines.
