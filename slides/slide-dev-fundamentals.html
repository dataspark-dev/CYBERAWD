SECURE CODE STARTS WITH YOU

Foundations Growing Practice Mature Practice

Before a pipeline or a reviewer ever sees your code, these habits are the first line of defence.

Input Validation Good Practice

Every input from a user, an API, or a file is untrusted until you check it — validate type, length, and format before you use it.

Hardcoded Secrets Risk

An API key or password committed to a repo is compromised the moment it's pushed — even a deleted commit stays in git history.

Dependency Review Before Merge Good Practice

Check a new package's publish history and maintainer reputation before merging — not just because the tests passed.

Code Review As A Control Good Practice

A second set of eyes on every PR — not a rubber stamp — catches what a rushed self-review misses.

This connects directly to this month's activities: the fake-dependency and PR-comment scenarios in Fault Finding and Decision Room are built on exactly these habits — a fresh package merged fast, a secret left in a config file, a PR approved without reading it.
Starting today: Never commit a secret, even in a private repo Check a new dependency's history before merging Read every PR you approve, don't rubber-stamp
