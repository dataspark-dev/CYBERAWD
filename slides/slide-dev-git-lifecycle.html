DEFEND EVERY STAGE OF THE LIFECYCLE

AppSec Secrets Git Lifecycle AI Code Audit Prompt Injection Golden Rules

A credential leak is caught fastest at the stage closest to where it happened — build defense into every stage, not just one.

Pre-Commit — Local Hook Scans Good Practice

A local pre-commit hook scans for credential patterns before code ever leaves your machine — the cheapest possible place to catch a leak.

Pull Request — Peer Review + Signed Commits Good Practice

A second set of eyes plus a verified commit signature confirms both the change and its author before merge — not a rubber stamp.

Pull Request — Automated Secret Scanning Good Practice

A dedicated scanner checks every diff for credential patterns a human reviewer can miss — a second, automated line of defense at the same stage.

Leak Reaches Main — Instant Revocation Required Risk

If a secret does reach a shared branch, treat it as compromised immediately — rotate/revoke it, don't just delete the line; git history keeps it forever.

This connects directly to this month's activities: the PR-comment and CI/CD-phishing scenarios in Fault Finding and Decision Room target exactly this pipeline — the same stages that catch a real leak are also where a fake request tries to blend in.
