YOUR PIPELINE IS PART OF THE ATTACK SURFACE

Foundations Growing Practice Mature Practice

Once code merges, the CI/CD pipeline that builds and deploys it becomes a target of its own.

Least-Privilege Deploy Credentials Good Practice

A deploy credential that can do everything is a credential worth stealing — scope every token to only what that specific job needs.

Long-Lived Static Deploy Keys Risk

A deploy key that never expires and never rotates is a standing target — prefer short-lived, scoped tokens issued per run.

Pipeline Config Reviewed Like Code Good Practice

A change to your CI/CD YAML can quietly add a step that exfiltrates secrets — review pipeline changes with the same rigor as application code.

Build Environment Isolated Good Practice

A compromised dependency inside a build step shouldn't be able to reach your production credentials.

This connects directly to this month's activities: the CI/CD credential-phishing scenarios in Fault Finding and Decision Room target exactly this layer — the pipeline that already holds real deploy access.
Starting today: Scope every CI/CD credential to least privilege Rotate long-lived deploy keys Review pipeline config changes like application code
[SECURE THE PIPELINE] GOLDEN RULE: A pipeline with standing, all-access credentials is one compromised dependency away from a full breach — scope, rotate, and review it the same way you would any other privileged system.
