AN AI FEATURE HAS A NEW ATTACK SURFACE

AppSec Secrets Git Lifecycle AI Code Audit Prompt Injection Golden Rules

Building with AI is different from just using an AI tool — the content your feature reads becomes something an attacker can talk to.

Direct Prompt Injection Risk

A user directly types an instruction meant to override your system prompt or safety rules — the classic “ignore previous instructions” attempt.

Indirect Prompt Injection Risk

A malicious instruction hidden inside a PDF, a website, or a document your RAG pipeline retrieves — the user never typed it, but your model reads and can act on it anyway.

Treat Retrieved Content As Untrusted Input Good Practice

Anything your AI feature reads from an external document, website, or RAG index is untrusted the same way user input is — it needs the same validation discipline as slide one of this section.

Constrain What The Model Can Actually Do Good Practice

Limit tool access and actions available to the model to only what the feature genuinely needs — an injected instruction can't cause damage the model has no permission to cause.

This is specifically for anyone building an AI feature, not just using one — the CI/CD and fake-dependency scenarios you already practice are about attackers reaching your pipeline; this is about attackers reaching your AI feature through the content it reads.
Starting today: Treat every retrieved document/website as untrusted input Limit what actions an AI feature's model can actually take Watch for instructions hidden inside external content your RAG pipeline pulls in
[PROMPT INJECTION] GOLDEN RULE: If your feature reads external content and acts on what it finds, that content is now part of your attack surface — validate and constrain it exactly like any other untrusted input.
